# 🔐 Network Traffic Analysis Using Wireshark

## 📌 Project Overview

This project focuses on **network traffic capture, packet analysis, endpoint identification, protocol analysis, and basic threat detection using Wireshark**.

The objective is to understand how network communication occurs at the packet level and identify potentially suspicious traffic by analyzing protocols such as **ICMP, DNS, TCP, and TLS**.

A controlled ICMP traffic scenario was also generated in a lab environment to demonstrate how repeated network traffic can be identified during security monitoring.

---

## 🎯 Objectives

* Capture live network traffic using Wireshark
* Analyze ICMP communication
* Investigate DNS queries and responses
* Analyze TCP connection establishment
* Identify encrypted TLS communication
* Identify source and destination endpoints
* Analyze network conversations
* Detect repeated ICMP traffic
* Understand basic network-based threat indicators
* Document findings in a security investigation format

# 📡 2. ICMP Traffic Analysis

### Wireshark Filter

```text
icmp
```

### Observed Communication

```text
Source      → Destination
192.168.5.121 → 8.8.8.8
```

### Analysis

ICMP Echo Request and Echo Reply packets were observed during connectivity testing.

The traffic demonstrates the standard ICMP communication pattern:

```text
Echo Request
      ↓
Destination
      ↓
Echo Reply
```

### Security Relevance

ICMP can be used for:

* Connectivity testing
* Network troubleshooting
* Host discovery
* Network reconnaissance
* ICMP tunneling
* Flood-based attacks

Therefore, abnormal ICMP frequency or unusual destinations should be investigated during security monitoring.

# 🔗 4. TCP Traffic Analysis

### Wireshark Filter

```text
tcp
```

TCP connection establishment was analyzed using the standard **three-way handshake**.

### TCP Handshake

```text
Client                    Server

   SYN  -------------------->

       <---------------- SYN-ACK

   ACK  -------------------->
```

### Observed Packets

* SYN
* SYN-ACK
* ACK

### Security Relevance

TCP analysis can help identify:

* Connection attempts
* Open services
* Port scanning
* Failed connections
* Abnormal connection rates
* Suspicious external communication

Useful Wireshark filters:

```text
tcp.flags.syn == 1
```

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

```text
tcp.flags.reset == 1
```

# 🔒 5. TLS / HTTPS Traffic Analysis

### Wireshark Filter

```text
tls
```

Encrypted TLS traffic was observed during HTTPS communication.

Since HTTPS traffic is encrypted, the application payload cannot normally be viewed directly without the appropriate decryption material.

However, network metadata can still provide useful information.

### Possible Metadata

* Source IP
* Destination IP
* Destination port
* TLS version
* TLS handshake information
* Server Name Indication (when available)
* Certificate information
* Connection timing

### Security Relevance

TLS traffic analysis can help detect:

* Suspicious encrypted connections
* Unknown external endpoints
* Unusual TLS behavior
* Potential command-and-control traffic
* Repeated encrypted connections

# 🚨 8. Suspicious Traffic Analysis

A controlled ICMP traffic scenario was generated against a lab/test environment to demonstrate basic network threat detection.

### Traffic

```text
Source:
192.168.5.121

Destination:
8.8.8.8
```

### Filter

```text
icmp
```

### Observation

Repeated ICMP packets were observed during the controlled test.

### Security Interpretation

Repeated ICMP traffic may be legitimate during testing or troubleshooting. However, unusually high-frequency ICMP traffic can also be an indicator requiring investigation.

Potential scenarios include:

* ICMP flooding
* Network reconnaissance
* Host discovery
* Connectivity testing
* ICMP tunneling

**Important:** Repeated ICMP packets alone do not prove malicious activity. Traffic frequency, timing, destination, packet size, and surrounding network behavior should be analyzed before classifying it as suspicious.
