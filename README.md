# Network Traffic Analysis Using Wireshark

## Project Overview

**Network Traffic Analysis Using Wireshark** is a practical cybersecurity and networking project focused on capturing, inspecting, filtering, and analyzing network packets in a Windows environment.

The project uses **Wireshark** to investigate network communications and identify important network characteristics such as:

* Source and destination IP addresses
* MAC addresses
* DNS queries and responses
* ICMP Echo Request and Echo Reply traffic
* TCP connections
* UDP communication
* TLS/HTTPS traffic
* Network endpoints
* Network conversations
* Potentially suspicious traffic patterns

The goal is to understand how devices communicate over a network and develop practical skills in **packet analysis, network troubleshooting, and basic network security monitoring**.

---

## Objectives

The main objectives of this project are:

1. Capture live network traffic using Wireshark.
2. Identify the local network interface and IP configuration.
3. Analyze Ethernet frames and MAC addresses.
4. Identify source and destination IP addresses.
5. Analyze ICMP traffic generated by ping.
6. Identify DNS queries and responses.
7. Analyze TCP connections and communication patterns.
8. Examine TLS traffic associated with HTTPS connections.
9. Identify active network endpoints.
10. Analyze conversations between network hosts.
11. Apply Wireshark display filters for investigation.
12. Identify unusual or potentially suspicious network behavior.
13. Document the investigation using screenshots and a technical report.

---

## Project Scope

This project focuses on **network traffic generated from a Windows system**.

The analysis includes:

| Area               | Analysis                                   |

# 2. Install Wireshark

Download Wireshark from the official website:

[Wireshark Official Website](https://www.wireshark.org/?utm_source=chatgpt.com)

During installation, make sure **Npcap** is installed.

Npcap allows Wireshark to capture packets from supported network interfaces.

After installation, open Wireshark.

# 3. Identify Network Configuration

Open Command Prompt:

```cmd
ipconfig
```

Example output:

```text
IPv4 Address : 192.168.5.121
Subnet Mask  : 255.255.255.0
Default Gateway : 192.168.5.1
DNS Server    : 103.143.168.2
```

Record the following information:

```text
Local IP:
Subnet Mask:
Default Gateway:
DNS Server:
Network Interface:
```

This information is useful when interpreting packets captured by Wireshark.

# 5. Generate Test Network Traffic

To create useful traffic for analysis, perform several normal network activities.

## ICMP Traffic

Open Command Prompt:

```cmd
ping 8.8.8.8
```

Example:

```text
Reply from 8.8.8.8: bytes=32 time=20ms TTL=117
```

# 7. Basic Packet Analysis

Each captured packet contains multiple protocol layers.

A typical packet can contain:

```text
Frame
  ↓
Ethernet
  ↓
IP
  ↓
TCP/UDP/ICMP
  ↓
Application Protocol
```

For example:

```text
Ethernet
    Source MAC
    Destination MAC

IPv4
    Source IP
    Destination IP

TCP
    Source Port
    Destination Port

TLS
    Encrypted Application Data
```

# 8. Ethernet and MAC Address Analysis

Select an Ethernet packet.

Expand:

```text
Ethernet II
```

Record:

```text
Source MAC Address
Destination MAC Address
EtherType
```

```text
Source MAC      : XX:XX:XX:XX:XX:XX
Destination MAC : XX:XX:XX:XX:XX:XX
EtherType       : IPv4
```

MAC addresses identify network interfaces at the Ethernet layer.

# 12. TCP Analysis

Use:

```text
tcp
```

Display filter.

Look for TCP connection establishment.

The normal TCP three-way handshake is:

```text
Client → Server : SYN
Server → Client : SYN, ACK
Client → Server : ACK
```

This establishes a TCP connection.

### Useful filters

Display SYN packets:

```text
tcp.flags.syn == 1
```

Display SYN packets without ACK:

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

Display TCP resets:

```text
tcp.flags.reset == 1
```

Display TCP retransmissions:

```text
tcp.analysis.retransmission
```

Display TCP errors:

```text
tcp.analysis.flags
```

Save:


# 18. Suspicious Traffic Investigation

The objective of suspicious traffic analysis is not to automatically classify every unusual packet as malicious.

Instead, investigate traffic that differs from expected network behavior.

Potential indicators include:

### Repeated Connection Attempts

Look for:

```text
Multiple SYN packets
Repeated connection failures
Repeated destination attempts
```

Filter:

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

---

### TCP Resets

Filter:

```text
tcp.flags.reset == 1
```

A large number of resets may require further investigation depending on the application and network environment.

---

### ICMP Anomalies

Investigate:

```text
High-volume ICMP
Unexpected destinations
Repeated ICMP requests
Unusual packet sizes
```

Filter:

```text
icmp
```

---

### Suspicious DNS Activity

Investigate:

```text
Large number of DNS requests
Repeated requests for unusual domains
Unexpected external domains
Unusual query patterns
```

Filter:

```text
dns
```

---

### Unexpected External Connections

Review:

```text
Statistics → Endpoints
Statistics → Conversations
```

Look for external IP addresses that are unexpected for the test environment.

Do not classify an address as malicious based only on the fact that it is external.
